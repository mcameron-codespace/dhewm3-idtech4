# AGENTS.md — dhewm3 (Doom 3 GPL source port)

dhewm3 is a cross-platform (Linux, macOS, Windows, FreeBSD) source port of DOOM 3, built on SDL + OpenGL + OpenAL. Primary source lives in `neo/`; CMake is pointed at `neo/`, NOT the repo root.

## Dev environment

- Toolchain: CMake (>= 2.6; versions >= 3.22 trigger FATAL_ERROR), GCC/Clang/AppleClang/MSVC. Other compilers are fatal.
- Default C++ standard: C++98 (IMGUI off) or C++11 (IMGUI on with SDL2/SDL3).
- Required deps: OpenAL (Soft), SDL (1.2/2.0/3 — 2.0 recommended). Optional: libcurl (server downloads), libbacktrace (better crash backtraces on non-Windows).
- Game data is NOT in this repo. DOOM 3 1.3.1 data required; BFG Edition is NOT supported.

## Build & test

Out-of-tree builds only.

List CMake options: `cmake -LH ../neo/` (run from the build dir)

### Linux (matches CI)
```
mkdir build && cd build
cmake ../neo/
make -j8
```
CI uses Ninja: `cmake -G Ninja -DDEDICATED=ON ../neo/` then `ninja`.

### macOS
Point CMake at OpenAL Soft. Intel Homebrew:
`cmake -DOPENAL_LIBRARY=/usr/local/opt/openal-soft/lib/libopenal.dylib -DOPENAL_INCLUDE_DIR=/usr/local/opt/openal-soft/include -S neo/ -B build`
Apple Silicon:
`cmake -DOPENAL_LIBRARY=/opt/homebrew/opt/openal-soft/lib/libopenal.dylib -DOPENAL_INCLUDE_DIR=/opt/homebrew/opt/openal-soft/include -S neo/ -B build`
`cmake --build build`
Dedicated server is NOT built on macOS (unsupported).

### Windows (MSVC, from CI)
```
cmake -A Win32 -DDHEWM3LIBS=/path/to/dhewm3-libs/i686-w64-mingw32 -DDEDICATED=ON -DTOOLS=ON -S neo/ -B build
cmake --build build/ --config RelWithDebInfo
```
For x64: `-A x64` + `x86_64-w64-mingw32` libs path. `DHEWM3LIBS` must be an absolute path.

Notable CMake options: `DEDICATED`, `HARDLINK_GAME`, `IMGUI` (default ON with SDL2/3), `SDL3`, `ASAN`, `UBSAN` (implies HARDLINK_GAME), `REPRODUCIBLE_BUILD`, `LINUX_RELEASE_BINS` (RPATH=$ORIGIN/libs), `ONATIVE`, `FORCE_COLORED_OUTPUT`.

### Test/lint
There is no test suite and no linter. CI validates by building for Linux (x86_64 + aarch64), macOS (aarch64), and Windows (x86 + x64 MSVC). `-Werror=dangling-reference` is active on GCC/Clang; several warnings are enabled or suppressed (see `neo/CMakeLists.txt`).

## Conventions

- Source tree: `neo/`. Modules in `neo/CMakeLists.txt`: `renderer/`, `framework/`, `cm/`, `tools/compilers/dmap`, `tools/compilers/aas`, `tools/compilers/roqvq`, `tools/compilers/renderbump`, `sound/`, `ui/`, `idlib/`, `game/`, `d3xp/`, `libs/imgui/`, `sys/`.
- `config.h` is GENERATED by CMake from `neo/config.h.in` into the build dir; `neo/sys/platform.h` includes it. Never hand-edit `config.h`.
- id Software style: C++ with heavy `id...` types from `idlib/`. `TypeInfo.cpp` uses `#define private public` / `#define protected public` (allowed via `-D_ALLOW_KEYWORD_MACROS`).
- Console variables (CVars): in console `cvarName value`, or on the command line `+set cvarName value`. Console is always available.
- Settings menu: `F10` by default (or type `dhewm3Settings` in console) — requires ImGui build (default with SDL2/SDL3).
- Two GUI systems exist in this repo:
  - Doom3 scripted GUI system: `.gui` files with `windowDef`/`listDef`/`choiceDef`, fixed 640x480 virtual-pixel space, rendered through the Doom3 renderer (HUD, main menu, PDA, in-game panels). dhewm3 extends it with CstDoom3 anchors (`cstAnchor`, `cstAnchorTo`, `cstAnchorFactor`), `scaleto43`, `cstNoClipBackground`, new GUI variables (`gui::cstAspectRatio`, `gui::cstWidth`, `gui::cstHeight`, `gui::cstHorPad`, `gui::cstVertPad`), the `CstScreenSizeChange` named event, and debug `set "print"` from scripts. Docs: `docs/GUIs.md`. A Windows MFC GUI editor exists in `tools/guied/` but does NOT support dhewm3 extensions.
  - Dear ImGui (immediate-mode): built-in ImGui ON by default with SDL2/SDL3 (C++11), OFF with SDL1.2. Provides the dhewm3 Settings Menu; backends compiled in are `libs/imgui/backends/imgui_impl_sdl2.cpp` or `imgui_impl_sdl3.cpp` + `imgui_impl_opengl2.cpp`, plus `imgui_demo.cpp`. Wrapped by `neo/sys/sys_imgui.cpp/.h` and `neo/framework/Dhewm3SettingsMenu.cpp`.
- Stack: 8 MB (`/STACK:8388608` MSVC, `-Wl,--stack,8388608` MinGW).

## Pitfalls

- CMake source dir is `neo/`, NOT the repo root. Pointing CMake at `.` will fail.
- Do not hand-edit `config.h` — generated per-build.
- No Makefile in the repo root. Out-of-tree CMake generates one. Makefiles under `neo/libs/imgui/examples/` are for upstream ImGui examples only.
- SDL2 and SDL3 are mutually exclusive; enabling both disables SDL2 with a warning.
- On macOS, OpenAL Soft must be found explicitly; Homebrew paths differ by architecture.
- `DHEWM3LIBS` must be absolute when cross-compiling; it also seeds `CMAKE_PREFIX_PATH` / `OPENALDIR` / `SDLDIR` env vars.
- A `build/` dir already exists in this checkout (prior build); out-of-tree builds should go elsewhere or clean it.
- When touching compiler flags in `neo/CMakeLists.txt`, note the existing `-Wno-*` suppressions and the `-Werror=dangling-reference` line — new code may trigger them.

## Engine startup — required assets and known blockers

The engine binary (`build/dhewm3`) can be built cleanly from this repo, but it will **not start** without game assets. This repo contains NO game data (no DOOM 3 1.3.1 .pk4 files, no scripts, no GUIs). The following are the hard and soft requirements to get past initialization.

### Hard requirements (fatal if missing)

1. **`default.cfg`** — `neo/framework/FileSystem.cpp:2703-2717` does `ReadFile("default.cfg")` after `Startup()`. If missing in `base/` (or `demo/` after fallback), it calls `common->FatalError("Couldn't load default.cfg")`. Must be a console-script text file (can be empty or minimal `seta` commands). Searched relative to the active game directory (`base/` by default).

2. **Game DLL** — `neo/framework/Common.cpp:2712-2754` (`LoadGameDLL()`) loads `base.so` (or `d3xp.so` for the expansion). The DLL must export `GetGameAPI` with matching `GAME_API_VERSION`. On Linux, resolved from `fs_gameDllPath`, next to the executable, `build/` (BUILD_LIBDIR), or install libdir. Missing → `common->FatalError("couldn't load game dynamic library '%s'")`.

3. **`script/doom_main.script` + `script/doom_defs.script`** — `neo/game/Game_local.cpp:342` calls `program.Startup(SCRIPT_DEFAULT)` where `SCRIPT_DEFAULT = "script/doom_main.script"`, and `Game_local.cpp:1890` calls `program.FindFunction("doom_main")`. The script compiler (`neo/game/script/Script_Compiler.cpp`) expects a C-like syntax. These are game-logic scripts and are NOT in this repo — they come from DOOM 3 1.3.1 data.

### Soft requirements (engine starts but console/loading-screen/rendering break)

- **Materials** `textures/bigchars`, `console`, `_white`, `splashScreen` — referenced with `makeDefault=true` during early init (`Common.cpp:2471`, `Console.cpp:422-424`). Missing → fallback material returned, but console text and loading screen are unusable.
- **Font atlas** for `textures/bigchars` — conventionally a TGA strip (see `FileSystem.cpp:229-230` pure-exclusion entries for `fonts/*.tga` and `dds/fonts/*.dds`).
- **Light materials** `lights/defaultPointLight`, `lights/defaultProjectedLight` — precached at `RenderSystem_init.cpp:2208-2209`. Missing → warnings, lights default to a fallback.
- **GUI files** (`guis/mainmenu.gui`, `guis/intro.gui`, etc.) — `Session.cpp:3027-3039` calls `uiManager->FindGui(...)`. Missing → `FindGui` returns NULL, GUI pointers are NULL; session continues but menu/intros don't show.

### Known engine-side blocker (not asset-related)

- **`Image_files.cpp:1357` hardcoded rejection of `lights/` paths:** `if ( com_machineSpec.GetInteger() >= 1 && imgName.Icmpn( "lights/", 7 ) == 0 ) { return false; }`. This unconditionally refuses to load ANY image whose stored name starts with `lights/` on real hardware (`com_machineSpec >= 1`, essentially all non-emulated GPUs). Light texture images MUST NOT be placed under a `lights/` directory — use a different prefix (e.g. `textures/lightdata/...`) and reference them in material `.mtr` files with a `map textures/lightdata/<name>.tga` entry. This is why light textures in `base/textures/lights/` will never load on real hardware even if the file exists.

### Procedural bootstrap generator

`generate_minimal_assets.py` (workspace root) produces a minimal `assets/base/` tree sufficient to get the engine past `default.cfg` and game-DLL load, with placeholder materials/textures/scripts. It does NOT include any copyrighted DOOM 3 content. Usage:

```
python3 generate_minimal_assets.py
./build/dhewm3 +set fs_basepath ./assets +set r_fullscreen 0 +quit
```

The generator produces:
- `assets/base/default.cfg`
- `assets/base/script/doom_defs.script` + `assets/base/script/doom_main.script` (minimal stubs — enough to get past `idGameLocal::Init`, but the engine will still stop at game-content-dependent init stages)
- `assets/base/materials/` — 6 `.mtr` files (`_default`, `textures/_white`, `textures/bigchars`, `textures/console`, `textures/splashScreen`, `lights/defaultPointLight`, `lights/defaultProjectedLight`)
- `assets/base/textures/` — 6 `.tga` files (`bigchars.tga`, `_white.tga`, `console.tga`, `splashScreen.tga`, `lightdata/defaultpointlight.tga`, `lightdata/defaultprojectedlight.tga`)

Note: light textures are deliberately placed under `textures/lightdata/` (not `textures/lights/`) to avoid the `Image_files.cpp:1357` `lights/` rejection.
